# Nzovu TypeScript SDK and MCP

A pnpm monorepo for the Nzovu gRPC client, generated protocol types and MCP server.
All packages are private at version `0.0.1-dev.0`. GitHub Actions runs validation
only. Packaging and publishing remain disabled.

| Workspace           | Purpose                                                        |
| ------------------- | -------------------------------------------------------------- |
| `@nzovu/proto`      | Generated protobuf codecs and gRPC service definitions         |
| `@nzovu/client`     | Promise-based queue, message, schedule, schema and DLQ clients |
| `@nzovu/mcp-server` | MCP stdio server; executable `nzovu-mcp`                       |
| `@nzovu/examples`   | Usage examples                                                 |

The client and proto outputs are CommonJS with TypeScript declarations. The MCP
server uses ESM. Client depends on proto; MCP depends on client. Both nested example applications are pnpm workspaces and are included in
`make check-examples` and CI.

## Development

Use the [devcontainer](.devcontainer/README.md), which pins Node 22.23.2 and
pnpm 10.16.0. Development tooling requires Node 22.12 or newer. Compiler and test dependencies come from `pnpm-lock.yaml`.

```sh
make install-dev
make build-all
make test-all
make typecheck
make lint
make format FORMAT_FLAGS=--check
make check-generated
make check-examples
make audit
pnpm run check:identity
```

`make ci` runs build, type, test, formatting, identity and example checks locally.
`make audit` checks locked dependencies. It does not start GitHub Actions,
package archives or publication. Local builds emit JavaScript and declarations
for tests. All package manifests remain private; `prepack` and `prepublishOnly`
reject packaging/publication. `.github/workflows/ci.yml` runs quality checks on
Node 22/24, and built SDK/MCP compatibility on Node 18/20/22/24 against the exact
server revision in `proto/SOURCE.json`. SQLite and PostgreSQL, API keys, TLS/mTLS,
all RPCs, claim lifecycle, stdio MCP and executable examples are covered. Archived
workflows remain inactive with `.disabled` extensions; no tags, archives,
releases or packages are generated by CI.

`pr.yml` runs the same validation for pull requests targeting `main` and merge
queues. Its `PR Check Success` job passes only when every quality and live matrix
job succeeds; failures, cancellations and skipped validation fail the gate.
The `PR quality gate` repository ruleset requires this GitHub Actions check and
an up-to-date branch before merging into `main`, with no bypass actors.

To run live checks locally, build that pinned server with `CGO_ENABLED=1 go build
-tags sqlite -o /path/to/nzovu .`, then provide a disposable PostgreSQL database:

```sh
export NZOVU_TEST_POSTGRES_DSN='postgres://nzovu:password@localhost:5432/nzovu?sslmode=disable'
make test-live SERVER_BINARY=/path/to/nzovu
```

The fixture verifies the server build revision, creates temporary TLS certificates
and SQLite databases, and stops all server processes after validation. Requires Go,
Python 3 and OpenSSL on PATH. Both backends are mandatory; missing configuration
fails instead of skipping tests. See [examples](packages/examples/README.md) for
local usage. SDK runtime compatibility includes Node 18.

## Protocol sources

`proto/SOURCE.json` records the immutable Nzovu server commit and SHA-256 checksum
of every vendored source. Generation uses the locked `protoc` and `ts-proto`
versions; it neither downloads source nor installs tools.

```sh
make check-proto
make gen-proto
make check-generated
```

For an intentional protocol update, pass an existing local server Git checkout
and its full commit SHA. Committed bytes are used, including when that checkout
has uncommitted edits:

```sh
make update-proto SOURCE=/path/to/nzovu COMMIT=<full-40-character-commit>
make gen-proto
make ci
```

Review changes to the manifest, protocols and affected client contracts together.
The gRPC service is `nzovu.api.queueservice.v1.QueueService` on port 9000.

## Client usage

Run from the workspace after `make build-all`:

```typescript
import { NzovuClient, Queue } from "@nzovu/client";

const client = new NzovuClient({
  connection: { address: "localhost:9000", insecure: true },
});
await client.connect();
try {
  await client.queues.createQueue(
    "tasks",
    Queue.QueueMetadata.fromPartial({
      type: Queue.QueueType.SIMPLE,
      defaultMaxAttempts: 3,
    }),
  );
  console.log(await client.queues.getQueueState("tasks"));
} finally {
  await client.disconnect();
}
```

TLS is the default; local plaintext requires `insecure: true`. Configure
`connection.tls` for custom CA/mTLS and `connection.apiKey` for authentication.
See the [client API](packages/client/README.md) for deadlines and lease ownership.

## MCP

After building, start the stdio server locally:

```sh
NZOVU_ADDRESS=localhost:9000 NZOVU_INSECURE=true pnpm --filter @nzovu/mcp-server start
```

MCP configuration uses `NZOVU_*` environment variables. See
[configuration and tools](packages/mcp/README.md). Protocol output uses stdout;
diagnostics use stderr.
